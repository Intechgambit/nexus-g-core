# Contributing to Nexus-G

Thank you for your interest in contributing to the Nexus-G platform and the Genomic Intelligence Analytics Tool (GIAT) engine! We welcome community contributions, bug fixes, and feature enhancements to our open-core infrastructure.

---

## 🏛️ License Framework & Scope of Contributions

Nexus-G is open-sourced under the **GNU General Public License v3.0 (GPLv3)**. 

### 1. Dual-Licensing Architecture
Intechgambit LLC operates on a dual-licensing business model:
* **The Community Tier (GPLv3):** Free, open-source infrastructure including standard GIAT genomic processing algorithms and basic database integrations. In alignment with GPLv3, any distributed derivative works or modifications to this core codebase must also be open-sourced under the GPLv3.
* **The Commercial Tier (Subscription):** Intechgambit LLC grants proprietary, commercial licenses to enterprise, clinical, and federal subscribers. This commercial tier bypasses GPLv3 copyleft requirements, unlocking advanced multi-omics synthesis, automated HIPAA compliance infrastructure, and bidirectional FHIR/EHR gateways.

### 2. Feature Scope
* We actively encourage community contributions to our open-source foundational framework, standard biological algorithms, and documentation.
* Proprietary enterprise modules are strictly maintained within our commercial licensing stream. Pull requests that overlap with our closed-source subscription roadmap will be redirected.

## 🛠️ Code of Conduct

We are committed to maintaining a welcoming, inclusive, and professional community. We expect all contributors to respect differing viewpoints, use welcoming language, and accept constructive feedback gracefully.

---

## 🐛 How Can I Contribute?

### 1. Reporting Bugs & Feedback
Before opening a new issue, please search the existing Issues tab. If filing a new bug report, explicitly detail the steps to reproduce the behavior, your deployment environment (Docker, OS, Python version), and relevant log files.

### 2. Submitting Pull Requests (PRs)
To contribute code directly to the open-core pipeline:
1. **Fork the Repository:** Create a local clone of your fork.
2. **Branch Structure:** Keep your branch names descriptive (e.g., `bugfix/resolve-api-timeout`).
3. **Tests & Style:** Include test coverage for new features and ensure your code complies with standard project linting parameters.
4. **Open a PR:** Direct your PR to our `main` branch with a comprehensive summary of changes.

---

## 🔒 Branch Protection & Security

* **Protected Main:** Direct pushes to the `main` branch are disabled. All code requires automated CI/CD passing checks and approval from an Intechgambit core maintainer.
* **Security Vulnerabilities:** **Do not open a public GitHub issue for security flaws.** If you discover a potential vulnerability within the data pipelines or API gateway, email our core team directly at security@intechgambit.com.
